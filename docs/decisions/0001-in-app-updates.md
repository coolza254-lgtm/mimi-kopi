# 0001: อัปเดตแอปจากภายในโปรแกรม

- สถานะ: ใช้งานแล้ว (accepted) ตั้งแต่เวอร์ชัน 0.2.0
- วันที่: 2026-10-25

## บริบท

ผู้ใช้ไม่อยากดาวน์โหลดตัวติดตั้งใหม่ทุกครั้งที่มีการแก้ไข และแอปต้องยังทำงานแบบออฟไลน์เป็นหลัก (spec §3.2 ข้อ 7) ไม่มีบัญชีและไม่มี telemetry (spec §9.2)

## การตัดสินใจ

- ใช้ปลั๊กอิน updater ของ Tauri 2 เช็กเวอร์ชันจาก manifest ที่โฮสต์บน GitHub Releases
- ตัวติดตั้งทุกเวอร์ชันต้องถูกลงนามด้วยกุญแจส่วนตัว และแอปตรวจลายเซ็นด้วยกุญแจสาธารณะที่ฝังไว้ในแอป
- เจ้าของขอให้แอปอัปเดตได้เองสะดวกที่สุด จึงเช็กเวอร์ชันใหม่ตอนเปิดแอปเป็นค่าเริ่มต้น และปิดได้ในหน้า **ตั้งค่า** การเช็กอ่านแค่ `latest.json` จาก GitHub Releases ไม่ส่งข้อมูลการฝึกออกไป และจะติดตั้งก็ต่อเมื่อผู้ใช้กดปุ่มอัปเดตเท่านั้น
- ออฟไลน์หรือยังไม่มี release ก็ไม่แสดงข้อผิดพลาดตอนเปิดแอป
- ก่อนติดตั้งทุกครั้งต้องสำรองฐานข้อมูล SQLite และรัน migration ตามเวอร์ชัน (ยังไม่มี SQLite ต้องทำเมื่อเพิ่มฐานข้อมูล)
- วิธีออกเวอร์ชันใหม่อยู่ใน [`../RELEASING.md`](../RELEASING.md)

## ผลที่ตามมา

- รีโปนี้เป็น public ดังนั้นกุญแจลงนามส่วนตัวต้องเก็บใน GitHub Secrets เท่านั้น ห้าม commit เด็ดขาด
- ห้าม commit ไฟล์เพลงหรือ SoundFont ที่ license ไม่อนุญาต
- ยังไม่มี code signing certificate ของ Windows ผู้ใช้อาจเห็นคำเตือนจาก SmartScreen ตอนติดตั้งครั้งแรก
- เดิมวางแผนไว้ Phase 6 แต่ทำก่อนตามคำขอของเจ้าของ เพื่อให้รับเวอร์ชันใหม่ได้ระหว่างพัฒนา
