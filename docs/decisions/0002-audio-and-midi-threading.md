# 0002: เธรดของเสียงและ MIDI

- สถานะ: ใช้งาน (accepted)
- วันที่: 2026-10-25

## บริบท

spec §7.3 ห้าม audio callback ทำ file I/O, query ฐานข้อมูล หรือ lock ที่ใช้เวลานาน และเปียโน, metronome, backing ต้องใช้ฐานเวลาเดียวกัน ส่วน `cpal::Stream` ไม่ใช่ `Send` บนทุกแพลตฟอร์ม

## การตัดสินใจ

- **เธรด `audio-control`** เป็นเจ้าของ stream ทั้งหมด การเปิดอุปกรณ์หรือเปลี่ยน SoundFont ส่งเป็นข้อความเข้าเธรดนี้ แล้วสร้าง stream ใหม่ (ปิดอันเก่าก่อนเพื่อคืนอุปกรณ์)
- **โน้ตไปถึง audio callback ผ่าน ring buffer แบบ lock-free (`rtrb`)** ขนาด 1024 ถ้าคิวเต็มจะทิ้งเหตุการณ์ แทนที่จะทำให้ฝั่ง MIDI ค้าง
- **ระดับเสียงเป็น atomic** callback อ่านได้โดยไม่ lock
- **callback ไม่จองหน่วยความจำ** บัฟเฟอร์ทั้งหมดจองตอนสร้าง stream
- **MIDI ใช้ callback ของ midir** แปลงข้อความด้วย `mimi-core` อัปเดตสถานะคีย์ ส่งคำสั่งเข้าคิวเสียง และส่ง event ไปที่ UI เวลาของเหตุการณ์มาจาก `Instant` ของแอปตอนที่ได้รับ
- **เธรด `midi-watch`** ตรวจรายการพอร์ตทุก 1 วินาที ถ้าพอร์ตที่เลือกหายไปจะปล่อยทุกคีย์ (ไม่มีโน้ตค้าง) และเชื่อมต่อใหม่เมื่อกลับมา
- **เลือกพอร์ตด้วยชื่อ** เพราะผู้ใช้จำได้และยังเหมือนเดิมหลังถอดเสียบ
- **เสียงพื้นฐานในตัว (`BasicPiano`)** ใช้เมื่อยังไม่มี SoundFont เพราะแอปไม่แถม SoundFont ตาม spec §2.2

## ผลที่ตามมา

- การเปลี่ยนอุปกรณ์เสียงหรือ SoundFont ทำให้โน้ตที่กำลังเล่นหยุด ซึ่งยอมรับได้เพราะเป็นการกระทำของผู้ใช้
- ยังไม่ได้ทดสอบบนเครื่อง Windows กับเปียโนและหูฟังจริง ค่า latency ยังไม่ได้วัด
- metronome และ backing track มีช่องระดับเสียงแล้ว แต่ยังไม่มีเสียง (Phase 2 และ 4)
